# 功能特性详解

Recordly 专为软件开发者、技术布道师、产品经理与内容创作者设计，将「高质量屏幕录制」与「轻量演示视频剪辑」深度整合。

---

## 屏幕与音频采集

### 屏幕捕获引擎
- **低 CPU 开销**：采用高效的底层捕获库（`mss`），支持全屏与多分辨率自适应录制。
- **自定义帧率**：支持 10 FPS 至 120 FPS 自定义帧率配置，默认为平滑的 30 FPS。
- **托盘静默运行**：录制开启后主窗口自动隐藏至系统托盘，避免录屏画面被主界面遮挡。

### 独立双通道音频采集
- **麦克风独立轨道**：基于 `sounddevice` 捕获高保真麦克风旁白（WAV 格式持久化）。
- **系统声音独立捕获**：通过 FFmpeg 独立捕获应用播放与系统音频。
- **双轨独立调节**：在时间线中，麦克风与系统声音各自拥有独立轨道与波形显示，支持单独静音或调节音量增益（0% 至 200%）。
- **麦克风后期补录**：录制完发现口误或讲解不清晰时，无需重新录制整屏。右键麦克风片段选择「补录音频」，录制新的旁白直接替换对应时间区段，原音轨自动静音。

## 全局光标追踪与特效

### 鼠标轨迹高精度采样
- 基于 `pynput` 进行全局光标坐标监控，录制过程中以毫秒级时间戳记录光标移动与点击事件。
- **点击波纹与高亮**：鼠标按下时自动生成扩散涟漪波纹，使观众能够清晰识别每一次点击动作。
- **光标平滑插值**：针对高分屏或快速移动场景，具备平滑轨迹算法，消除跳帧抖动。
- **自定义光标样式**：支持在设置中自由配置光标尺寸（16 至 96 像素）、明暗主题（Dark/Light）及光标类型（经典箭头、圆点、聚光环）。

## 演示级时间线剪辑

### 时间线核心交互
- **直观标尺与播放头**：单击标尺精确定位时间码，双击时间线空白区域立即从该位置开始播放。
- **时间线缩放**：支持 `Ctrl + 滚轮` 以鼠标指针为中心缩放时间轴，微观微调与宏观总览无缝切换。
- **智能吸附对齐（Snapping）**：拖动视频与音频片段时，自动吸附到播放头或其他片段边缘，并显示对齐引导虚线。
- **多选与批量管理**：按住 `Ctrl + 单击` 支持多片段加入多选区，支持批量移动、统一调速或批量删除。

### 片段剪辑与控制
- **无损裁剪（Trim）**：鼠标悬停在片段边缘即可直接拖拽裁剪入点与出点（最少保留 0.5 秒）。
- **播放头一键拆分（Split）**：按快捷键 `X` 或右键菜单，在当前播放头位置快速将片段一分为二。
- **连续变速**：支持 0.25x、0.5x、1.0x、1.5x、2.0x 变速播放与导出，方便快进枯燥等待环节。
- **完整撤销与重做**：基于标准命令模式（Command Pattern），移动、拆分、音量调整、补录等全量操作均支持 `Ctrl+Z` 撤销与 `Ctrl+Shift+Z` 重做。

## 智能缩放（Zoom Track）

- **专属缩放轨道**：在时间线的「缩放」轨道双击即可添加一个缩放片段。
- **可视缩放框**：在预览区直观拖动蓝色视框决定放大目标区域（如某段代码、某个按钮或菜单），拖拽四角调整缩放比例（10% 至 90%）。
- **平滑过渡**：播放到缩放区间时，画面自动以平滑的摄像机镜头运镜放大至焦点区域，并在片段结束时平滑恢复全景。

## NVENC 硬件加速与导出

### 导出规格与画幅
- **MP4 与 GIF 导出**：支持输出标准 H.264 编码的 MP4 视频，或适合嵌入文档与 GitHub README 的循环播放 GIF。
- **多分辨率预设**：提供 4K (2160p)、2K (1440p)、1080p (Full HD)、720p (HD)、480p 及自定义分辨率。
- **主流社交比例**：内置 16:9（横屏视频）、9:16（移动端竖屏）、1:1（方形）、4:3 等宽高比，支持自动中心裁剪与自由画面裁剪。

### 导出性能
- **NVIDIA GPU (NVENC) 硬件加速**：针对配备 NVIDIA 显卡的 Windows 与 Linux 设备，提供原生 NVENC GPU 编码加速选项，大幅降低导出等待时间与 CPU 占用。
- **异步工作线程**：视频导出在后台独立工作线程执行，界面保持流畅响应，支持随时安全取消。

## 工程持久化与安全性

- **录制即持久化**：录制完成自动在 `~/Recordly/projects/` 创建专用工程目录，包含原始序列帧、双轨音频与结构化 `project.json`。
- **原子化文件写入**：工程配置写入采用临时文件替换模式，防止意外断电或程序崩溃损坏历史数据。
- **异常恢复机制**：启动时自动扫描并清理过往未正常结束的临时残留帧；若录制过程因外部因素异常中断，只要已采集到有效帧数据，项目将自动保存并提示用户可以继续打开编辑。
